Please implement the following release-gate policy in the main Replit project.

**Goal:** Remove the recurring manual release-approval bottleneck for routine deployments and verified fresh installs, while preserving protections for existing databases.

1. **Routine migrations:** Automatically allow migrations that pass release validation, integrity checks, and the supported migration policy.
2. **Fresh empty database:** Permit unattended initialization only when the database is independently verified as empty, the database and PostgreSQL cluster identities match the configured target, encryption and recovery prerequisites pass, and the release artifact is validated and integrity-checked. Do not infer that a database is empty merely because `alembic_version` is absent.
3. **Existing or populated database:** Keep explicit operator approval for destructive or data-sensitive migrations, encrypted-data changes, and protected bootstrap operations.
4. **No approval bypass:** Do not merely change `reviewed_candidate_requires_human_release_approval` to another status or remove hash checks. Replace the broad manual gate with a documented, enforceable policy that automatically authorizes only the safe cases above.
5. **Targets remain fixed:** Fresh-install final target `0039_communication`; prepare target `0031_role_hostnames`; retirement cap `0034_shared_phone_countries`.
6. **Tests:** Add positive and negative tests for empty databases, populated databases, missing revision tables, mismatched database/cluster identities, tampered manifests, invalid migration graphs, missing encryption configuration, and protected bootstrap.
7. **Release validation:** Run the complete release gate and browser test suites. Report every remaining failure honestly.
8. **Deliverables:** Commit the change on the main project branch and report the exact commit SHA, changed files, test results, and documented VPS commands.

Do not run migrations, deploy, restart containers, or alter VPS data as part of this code change.
