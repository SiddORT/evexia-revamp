EVEXIA ADMIN PORTAL — STRUCTURE & ZONE MASTER

We are now moving to the Admin Portal of the EVEXIA Life Sciences application.

IMPORTANT:
This is an existing React JS project that you have already started.

DO NOT rebuild the application from scratch.

Before making changes:
1. Inspect the existing project structure.
2. Inspect all existing components.
3. Identify reusable components already created.
4. Reuse existing components wherever possible.
5. Extend existing components when appropriate.
6. Do NOT create duplicate components with different names for the same purpose.
7. Maintain the existing EVEXIA design system, colors, typography and styling.

==================================================
TECHNOLOGY
==================================================

Use:

- React JS
- JavaScript ONLY
- .js / .jsx files

DO NOT use TypeScript.

Follow strict, production-quality React coding standards.

Use:
- Functional components
- React Hooks where appropriate
- Proper component composition
- Proper separation of concerns
- Reusable components
- Clean naming conventions
- Small, focused components
- No unnecessary duplication
- No unnecessary inline logic
- No huge monolithic components

Do not introduce unnecessary libraries or dependencies.

==================================================
SEPARATION OF CONCERNS
==================================================

Do not put everything inside ZoneMaster.jsx.

For example:

Page
  ↓
Zone Master UI
  ↓
Reusable Table / Form / Modal
  ↓
Hook for zone-related state
  ↓
Service/API layer

Keep API communication separate from presentation.

If APIs are not available yet, use mock/local data in a way that can easily be replaced by an API service later.

==================================================
STRICT REACT CODING STANDARDS
==================================================

Follow these rules:

- JavaScript only
- Functional components
- Hooks instead of class components
- Meaningful component names
- Meaningful variable names
- Avoid duplicated JSX
- Avoid unnecessary state
- Avoid unnecessary re-renders
- Keep components focused
- Keep business logic out of presentational components
- Keep API calls out of UI components
- Reuse shared components
- Avoid deeply nested components where unnecessary
- Avoid giant files
- Avoid hardcoded repeated values
- Use constants where appropriate
- Keep styling consistent with the existing design system
- Keep accessibility in mind
- Use semantic HTML where appropriate

Do not rewrite working existing components just for the sake of changing them.
